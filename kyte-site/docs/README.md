# Kyte website documentation

Start with the root `WEBSITE_PROGRESS.md` for verified release status and the next content task.

- `template-system.md`: active page templates, shared UI rules and ownership.
- `audit-and-release.md`: repeatable responsive, navigation, loading, archival and release process.
- `branding-story/`: current Branding landing design and interaction notes.
- `audits/`: dated findings and evidence. Earlier reports describe the state on that date.
- `release/`: exact commits, deployment identities, rollback target and post-release checks.
- `history/`: preserved progress logs and superseded design notes. Historical decisions do not override current rules.

The root IA owns routes. The root SEO playbook owns page intent, proof and editorial requirements. `/design-system` and `src/app/globals.css` own the visual system. Component source owns implementation details. Avoid copying the whole current state into every report.
